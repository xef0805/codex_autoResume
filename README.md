# Codex 额度恢复续跑助手

> **自用项目**：仅供本人在自己的 Windows 和 Codex 环境中使用，不保证其他设备或后续版本兼容。

这是一个用于 Windows Codex 桌面应用的本地小工具。先做好功能，以后需要时再选择一个聊天启用。当前没有绑定聊天，没有向任何聊天发送续跑消息，也没有注册开机启动或后台定时任务。

## 怎么用

1. 保持 Codex 桌面应用运行并登录。
2. 双击本目录的 **Start-AutoResume.cmd**。
3. 在下拉列表中选择一个本机 Codex 聊天，点击 **开启监控**。这一步授权工具在满足下面的条件后向这个聊天发送续跑指令。
4. 继续在 Codex 中正常工作。工具每 60 秒检查这个聊天一次。
5. 如任务因 5 小时额度耗尽而失败，工具等待额度恢复，再向原聊天发送一次继续指令。

点击 **停止监控** 或关闭助手窗口即可取消监控；这不会中断已经开始的 Codex 任务。再次打开助手必须重新选择聊天并开启。需要电脑保持唤醒、Codex 和助手窗口保持运行；睡眠期间不能检查。

**模拟验证** 按钮只运行本地测试，不会向任何真实聊天发送消息。

从 GitHub 重新克隆时，需要先将 `local_settings.example.json` 复制为 `local_settings.json`，填入一个用于管理助手的本机 Codex 聊天 UUID。这个管理聊天用于应用接口的调用上下文，和下拉框中选择的待监控聊天是两个独立的角色。在管理聊天输入 `/status` 可以查看其聊天 ID。当前这台电脑已配置；真实聊天 ID、运行状态和缓存均通过 `.gitignore` 排除，不上传 GitHub。

## 触发条件

必须同时满足：

- 只监控你明确选中的一个本机 Codex 聊天。
- 最近一轮状态是 `failed`，且错误代码是 `usageLimitExceeded`。
- 工具实际观察到这一轮失败时，标准 Codex 额度桶的 300 分钟窗口已用完。普通网络错误、用户主动中断和正常完成不会触发。
- 随后读到 5 小时窗口已恢复，并且服务端明确报告 `ordinaryUsageAllowed: true`。周额度、账号额度或支出限制仍阻止使用时继续等待。只等自然恢复，不兑换重置券，不购买或使用额外额度。
- 发送前再检查一次聊天，没有发现新的任务轮次、正在运行或用户等待状态，且用户没有停止监控。

每一个失败轮次最多发送一次。如果自动恢复后的新一轮又因额度失败，可等待下一次恢复。原聊天的上下文、模型和权限不由本工具覆盖。

发送前先保存去重记录。若发送回执超时或结果不明确，工具停止监控，要求在原聊天核实，不盲目重发。重新打开工具仍保留这些记录。

## 使用边界

- 这是独立的本地助手，不是给 Codex 添加了一个内置设置。
- 官方公开文档说明了额度查询、原聊天继续和排队消息能力；本工具实际使用的是当前桌面版本自带的 **app-tools 本地命名管道**。这个接入方式属于版本相关的内部接口，升级后可能需要适配。
- 已验证当前机器能读取额度、聊天列表和最近一轮状态。模拟验证覆盖了恢复、去重、周额度阻塞、主动中断、账号变化等场景。**尚未用真实额度耗尽的任务验证自动续跑结果**；当前没有合适任务，不能把模拟通过当作真实续跑成功。
- 如果额度已经恢复以后才开启工具，且工具没有观察到该次失败时的 5 小时额度耗尽状态，它会保守地不处理这次旧失败。应在开始长任务时开启监控。
- 用户在发送前最后一次检查之后又立即操作聊天时，存在很短的并发窗口；当前应用工具没有提供“仅当失败轮次不变才发送”的原子接口。需要取消时先停止本工具。
- 如果在 Codex 中通过目标暂停等方式停止工作，却没有形成新的聊天轮次或 `interrupted` 状态，工具未必能识别；请同时停止本工具。
- 这里只处理本机 Codex 聊天和标准 `codex` 额度桶；不处理 ChatGPT 聊天、远程执行环境或其他额度桶。
- 短暂断线时只重试读取状态，不重复发送。账号变化或发送结果不明确时停止。

## 本机要求

当前机器已验证 Python 3 和 Tkinter 可用，启动脚本优先使用现有的 `%USERPROFILE%\miniforge3\pythonw.exe`，其次使用 PATH 中的 `pythonw.exe`。无需安装第三方 Python 包，也不需要填写 API key。

连接仅通过 Codex 自带的本地应用工具管道；不读取或复制登录令牌，不修改 Codex 安装目录、配置文件或聊天数据库。多个 Codex 应用连接同时存在且无法唯一定位时，工具会拒绝连接。

本目录包含仅保存在本机的 `local_settings.json`（管理聊天编号），运行后可能产生 `state.json`（目标聊天编号、账号编号、等待状态及去重记录）、`app.lock`（防止重复打开）和 Python 缓存。聊天正文和额度查询结果不会写入磁盘日志。删除本目录即可移除工具；删除 `state.json` 会丢失去重记录，应仅在监控停止并核实原聊天后操作。

## 验证与文件

- `app.py`：选择聊天、启停监控和状态窗口。
- `core.py`：触发条件、恢复判断和持久化去重。
- `bridge.py`：与当前 Codex 桌面应用的本地接口通信，只有四个必要工具在允许列表中。
- `test_monitor.py`：15 项模拟测试，不连接真实聊天。
- `VERIFICATION.md`：本次验证记录。

只读连接检查：`python app.py --check`。本地测试：`python test_monitor.py`。
